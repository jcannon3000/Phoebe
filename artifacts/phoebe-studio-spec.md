## Verdict

## Chain (ordered)

- **0. Capture (realtime, unchanged)** — `getUserMedia → MediaRecorder (pickMime: audio/mp4 AAC on iOS, webm/opus elsewhere)` · echoCancellation:true, noiseSuppression:true, autoGainControl:true, channelCount:1; MAX_MS=10000
  - _Records the raw blob. EC gives free early-reflection (light de-reverb). No realtime DSP — all shaping is offline._
- **1. Decode → mono PCM @48k** — `AudioContext.decodeAudioData (callback+promise form for Safari) → OfflineAudioContext(1, ceil(dur*48000), 48000)` · PROC_RATE=48000; read decoded.sampleRate dynamically, never assume; stereo auto-downmixes to the mono ctx
  - _Offline render is sample-accurate and faster than realtime; 48k so the BS.1770 K-weighting coeffs are exact. Already implemented (decode/renderChain)._
- **2. High-pass (rumble/plosive)** — `BiquadFilterNode 'highpass'` · freq 80 Hz, Q 0.707 (12 dB/oct). Already in renderChain.
  - _Sheds handling/HVAC/plosive thump without stripping the 100-250 Hz warmth that makes a voice feel close._
- **3a. RNNoise denoise (NEW — biggest upgrade)** — `RNNoise-WASM one-shot offline loop on the Float32 PCM, BETWEEN highpass and warmth shelf` · 48k, 480-sample (10ms) frames, Float32↔Int16 convert; blend 80% wet / 20% dry to keep breath/intimacy; cap effective reduction ~6-12 dB
  - _Learned suppression of broadband/non-stationary room noise with far less musical-noise than spectral gating. The single thing that most separates 'phone' from 'studio'. Lazy-load the WASM; if it fails, skip (chain still works)._
- **3b. Warmth low-shelf** — `BiquadFilterNode 'lowshelf'` · freq 200 Hz, gain +warmthDb per preset (studio +2, warm +3.5, intimate +4, radio +1.5). Already in renderChain.
  - _Proximity-effect chest/closeness of a near mic — the core of intimacy. Bias warm for a prayer._
- **4. Subtractive EQ (mud + box) — BEFORE compression** — `2× BiquadFilterNode 'peaking'` · 300 Hz Q1.0 gain mudCutDb (−1.5 to −3); 500 Hz Q1.2 gain boxCutDb (−1 to −2.5). Already in renderChain.
  - _Clears congestion so the voice reads clear, not boxy. Cuts go before the compressor so compression doesn't amplify mud._
- **5. Presence + air (additive EQ)** — `BiquadFilterNode 'peaking' + 'highshelf'` · presence 3200 Hz Q0.8 gain +presenceDb (studio +3, intimate +2.5, radio +4); air highshelf 9000 Hz gain +airDb (+1 to +3). Already in renderChain.
  - _Presence = articulation/'in the room with you'; air = breath/openness. Kept modest (≤+4) so it's intimate, not harsh/fatiguing._
- **6. Anti-alias lowpass** — `BiquadFilterNode 'lowpass'` · freq OUT_RATE*0.475 ≈ 11.4 kHz, Q0.707. Already in renderChain.
  - _Bandlimits before the eventual 24 kHz decimation so the downsample doesn't alias._
- **7. De-esser (NEW — add to renderChain)** — `Parallel split-band: BiquadFilter 'bandpass' 6.5 kHz Q~2 → DynamicsCompressor (hard) → phase-matched subtract, OR simplest v1: a dynamic peaking notch` · band 5-8 kHz; 3-6 dB GR on sibilant peaks only; attack 0.001, release 0.04; place AFTER compressor conceptually — in WebAudio insert between presence and comp is acceptable for v1, ideally post-comp
  - _Compression brings sibilance up; without de-ess the +presence/air boosts make S's spit. Currently MISSING from renderChain — add it. v1 can ship without and add this in the limiter pass._
- **8. Compressor (level/intimacy)** — `DynamicsCompressorNode` · threshold compThresholdDb (−22 to −28 per preset), knee 24, ratio compRatio (2.5-4.0), attack 0.004, release 0.18. Already in renderChain.
  - _Raises the quiet tail (breath, soft consonants) toward peaks — THIS is what creates intimacy/closeness. Soft knee, slow-ish release keeps it un-pumped._
- **9. Harmonic saturation (warmth)** — `WaveShaperNode, oversample '4x', tanh curve` · drive 0..1 → k=1+drive*4 (1..5), normalized; saturation per preset 0.18-0.30; ~15-30% perceived. Already in makeSaturationCurve.
  - _Even-order harmonics thicken the fundamental = 'analog warmth/closeness', softens transients = 'smooth not digital'. Drive kept low to preserve voice._
- **10. Downward expander (silent gaps)** — `JS envelope follower on Float32 PCM (expand())` · openThresh = measured-floor ×2.8; floorGain = expanderDb (−10 to −16); attack 5ms, release 80ms, 10ms detector. Already implemented.
  - _Pushes room tone DOWN between words — the biggest 'studio vs phone' tell. NOT a hard gate: leaves a low residual floor so pauses don't go uncanny-dead._
- **11. LUFS measure + normalize** — `integratedLufs() (hand-rolled BS.1770 K-weight biquads + 400ms/75% gated mean) → single static Gain` · target targetLufs (−14 radio … −17 intimate, −16 default); gainDb = target − measured; gain clamped ≤8 (≤+18 dB) so noise isn't over-boosted; guard NaN/−Inf→gain 1. Already implemented.
  - _Every memo lands at a consistent broadcast level. Static gain (not a compressor) preserves micro-dynamics = presence._
- **12. True-peak limiter (UPGRADE from soft-clip)** — `Replace normalizeAndLimit()'s tanh soft-clip with a JS look-ahead brickwall on 4× upsampled signal` · ceiling −2.0 dBTP (ceilLin 0.794) — TIGHTER than current 0.89 because output is WAV→fine, but margin protects if ever re-encoded lossy; 1.5ms (~72-sample) lookahead, instant attack via the delay, release 60ms (relCoef=exp(-1/(0.06*fs)))
  - _The current tanh soft-clip is a sample-peak fold, not a true-peak limiter — inter-sample peaks can still poke through after a static +gain. A look-ahead brickwall guarantees 'never clips'. v1 may keep the tanh soft-clip but tighten the ceiling to −2 dB; the brickwall is the next-iteration upgrade._

## Loudness
Already implemented correctly in studioVoice.ts and should be kept. Measure integrated loudness with hand-rolled ITU-R BS.1770 / EBU R128: two cascaded K-weighting biquads (stage 1 high-shelf b0=1.53512485958697 b1=-2.69169618940638 b2=1.19839281085285 a1=-1.69065929318241 a2=0.73248077421585; stage 2 RLB high-pass b0=1 b1=-2 b2=1 a1=-1.99004745483398 a2=0.99007225036621 — exact at 48k, which is why we render at PROC_RATE=48000), then 400 ms blocks at 75% overlap (block=19200, hop=4800 samples), absolute −70 LUFS gate, then −10 LU relative gate, average the surviving blocks' mean-SQUARE (not dB). TARGET = −16 LUFS integrated for spoken-word/podcast on phone speakers (Apple spec) — per-preset: studio/warm −16, radio −14 (forward/loud), intimate −17 (closer/softer). Apply as ONE static gain: gainDb = target − measured, gainLinear = 10^(gainDb/20), clamped ≤8× (≤+18 dB) so a hissy quiet prayer isn't over-amplified; guard −Inf/NaN (pure silence) → gain 1 so you never multiply silence by infinity. Then the true-peak stage: v1 keeps the existing tanh soft-knee fold but TIGHTEN the ceiling from 0.89 (−1 dBFS) to −2 dBTP (0.794) as a lossy-safety margin; the iteration-2 upgrade is a real 4×-oversampled look-ahead brickwall limiter at −2 dBTP (lookahead 1.5 ms, release 60 ms) for a true 'never clips' guarantee, since a static +gain creates inter-sample peaks the sample-peak fold can miss. Keep LRA tight (<7 LU) — the compressor already enforces this.

## Encoding
DECODE IN: AudioContext.decodeAudioData handles the captured audio/mp4(AAC)/webm-opus blob → PCM (decode is universally supported even though re-ENCODE to those codecs is not). ENCODE OUT: 16-bit mono WAV via the existing zero-dependency encodeWav() (44-byte RIFF header + Int16 LE). SIZE MATH IS THE HARD CONSTRAINT — measured against the 900 KB encrypted base64 cap (encryptVoice base64-expands ~1.33×): 48 kHz WAV = 960 KB raw → ~1.28 MB base64 → EXCEEDS the cap, DO NOT SHIP 48k WAV. 24 kHz WAV (what studioVoice outputs now, OUT_RATE=24000) = 480 KB raw → ~638 KB base64 → FITS. 16 kHz WAV = 320 KB raw → ~426 KB base64 → fits with comfortable margin if you want safety or longer clips. RECOMMENDATION: keep 24 kHz mono 16-bit WAV as the default output — voice is full and warm there and it clears the cap by ~260 KB. The anti-alias lowpass at 11.4 kHz already protects the 24k decimation. If you ever need more headroom or a future longer memo, drop to 16 kHz (telephone-plus, still fine for warm intimate voice) before reaching for a codec. A WASM Opus encoder (opus-encdec/opus-media-recorder, ~few hundred KB, 24-32 kbps → ~30-40 KB for 10s) is a SIZE/bundle optimization, NOT required to ship — defer it. Do NOT use WebCodecs AudioEncoder (undefined on iOS until Safari 26). Re-encoding via MediaStreamDestination+MediaRecorder is forbidden — that's the realtime path that records silence on iOS.

## Presets

- Radio: forward announcer — least warmth (+1.5), deepest mud/box cuts (−3/−2.5), brightest (presence +4, air +3), tightest comp 4:1 @−28, expander −16, louder target −14 LUFS
- Intimate: a whisper near the ear — most warmth (+4), least cutting, gentle dynamics (comp 2.5:1 @−22), most saturation (0.30), softest expander −10, quietest/closest target −17 LUFS
- Off: levelled-only — skip tone/dynamics, just resample + LUFS-normalize to −16 + true-peak limit (a safety/A-B baseline that's still consistent loudness)

## Perf budget
For a 10s mono clip the whole offline pipeline is comfortably sub-second to ~1s on modern devices, a few seconds worst-case on an iPhone 8/SE on iOS 15 (scalar WASM, no SIMD). Breakdown: decode ~tens of ms; offline tone/dynamics render (renderChain) is non-realtime and typically faster than realtime (<0.5s); expander + hand-rolled K-weight LUFS are simple O(n) array loops over ~480k samples — single-digit ms each, run TWICE (before/after) so still <50ms; RNNoise (when added) ~150 frames, well under a second scalar; resample-to-24k is a second short offline render; WAV encode is a DataView loop, ms. Memory: a 10s 48k mono Float32 buffer is ~1.9 MB; a few copies in flight = under ~10 MB peak — trivial. Keep it non-blocking and snappy: (1) lazy-load the RNNoise WASM once and cache it so the record tap and People page stay instant; (2) REUSE/close AudioContexts (WebKit leaks/crashes after ~2028 OfflineAudioContext instances — studioVoice already closes its decode ctx in finally; ensure render/resample ctxs are GC'd); (3) run enhance inside the 'Polishing…' state so the latency is visible-but-calm, not a frozen UI; (4) since it's all offline array math after startRendering, it won't glitch the way a realtime worklet would. Budget a 'too slow / threw' fallback to sending raw so a low-end device never blocks a prayer.

## Fallbacks
Layered graceful degradation, never block a send: (1) studioSupported() false (no OfflineAudioContext) → skip enhance entirely, send the raw recorded blob with its original mime — exactly today's behavior. (2) enhanceVoice() throws (decode error, truncated/empty render, ctx never reaches running) → catch in onstop, send the original blob; studioVoice already rejects rather than returning garbage, so the caller just falls back. (3) RNNoise WASM fails to load or init → skip the denoise stage only; the rest of the chain still renders (denoise is an optional insert, not a hard dependency). (4) iOS on-device validation fails (offline render returns silence/truncated — must be TESTED on a real iOS 15 device, not simulator) → ship iOS with preset 'off' (levelled-only: resample + LUFS-normalize + limit, no tone graph) or fall back to the original light realtime chain that exists today, and escalate to the native AVAudioEngine plugin stretch goal. (5) Output WAV unexpectedly over the 900 KB base64 cap → drop OUT_RATE to 16 kHz and re-encode, else send original. (6) Guard the silence/degenerate LUFS case (already done: −Inf/NaN → gain 1) so a silent clip is never multiplied by infinity. The invariant: enhancement is best-effort polish, never a precondition for sending a prayer.
